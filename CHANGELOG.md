## 3.4.62+125

### НАЙДЕНА И ИСПРАВЛЕНА ПРИЧИНА ПАДЕНИЯ ВСЕХ СБОРОК: конфликт имени `XFile`

**Причина (реальная, в Dart-коде, а не в Android-тулчейне):**

`lib/measure_media.dart` импортировал ДВА пакета, которые оба экспортируют
класс `XFile` (из `cross_file`):

```dart
import 'package:image_picker/image_picker.dart';   // экспортирует XFile
import 'package:share_plus/share_plus.dart';       // тоже экспортирует XFile
```

Одно имя из двух библиотек — это **ошибка компиляции** Dart:

```
The name 'XFile' is defined in the libraries
'package:image_picker/image_picker.dart' and
'package:share_plus/share_plus.dart'.
```

Файл `measure_media.dart` появился ровно в **3.4.30+93** (фото проёма + PDF +
отправка на сервер) — с этого момента и падали ВСЕ сборки (3.4.30 … 3.4.61).
`XFile` в этом файле используется трижды (`PhotoStore.add`, `Share.shareXFiles`),
поэтому ошибка срабатывала всегда.

**Почему не было видно:** шаг `flutter analyze` в workflow стоял с `|| true`,
а `flutter build apk` падал на компиляции Dart — красные строки Gradle уводили
в сторону Android-тулчейна, хотя Dart-код просто не собирался.

**Исправление (`lib/measure_media.dart`):**

- `XFile` берётся **напрямую из `cross_file`** — единственный источник имени
- из `image_picker` и `share_plus` имя **скрыто** (`hide XFile`)
- поведение не изменилось: камера, галерея, миниатюры, удаление, PDF-лист
  и отправка на сервер работают как были

**Диагностика на будущее (`.github/workflows/build.yml`):**

- шаг `Analyze` теперь пишет лог в `analyze.log` и **печатает ошибки Dart прямо
  в лог Actions** (`grep "error •"`)
- шаг «Показать ошибки сборки» дополнительно выводит `analyze.log` — если
  сборка упадёт снова, причина будет видна сразу, без догадок
- после `flutter create` удаляется `test/widget_test.dart` (шаблон создаёт его
  с несуществующим `MyApp` — он засорял analyze и прятал реальные ошибки)

**Не тронуто:** дерево, мастер, шаг размеров, АВТО-длины, чертёж по ГОСТ,
визуальный замер, смета, история, замерный лист, фото, фон, кнопки, логика

## 2.4.0+43

### Реалистичный ПВХ-профиль и объёмные инструменты на своих орбитах

**Ключевое исправление — окно было вывернуто наизнанку.**
В рендерере `+Z` — дальше от камеры. Все выступающие детали (ручка, петли,
штапик, отлив) строились в `+Z`, то есть **за стеклом** — поэтому окно выглядело
плоской картинкой. Теперь «лицо» окна смотрит в `−Z`, и все детали выступают
навстречу зрителю.

**Профиль окна (`lib/viewer3d.dart`):**

- **внутренняя стенка рамы** — тёмная полоса по внутреннему периметру, уходит
  вглубь на 30 мм: профиль перестал быть плоской рамкой
- **фаска** по передней кромке всех четырёх брусьев
- **воздушная камера** — тёмная канавка по центру каждого бруса (деталь ПВХ-профиля)
- **штапик** — тонкая светлая рамка вокруг каждого стеклопакета
- **импост** — белый, с канавкой по центру
- **стеклопакет** — градиент неба из 5 полос (сверху плотнее, снизу прозрачнее)
  и **двойной диагональный блик**
- **ручка** — серебристая: площадка, рычаг, упор; выступает на 82 мм к камере
- **петли** — тёмный металл с серебристой осью, две на створку (10 % / 90 %)
- **подоконник** — плита + капельник (отлив) + передняя кромка, выступ 122 мм

**Инструменты — объёмный каркасный стиль:**

- **призрачные кольца-траектории** у каждого инструмента — видно, что ось своя
- **рулетка**: шестигранный барабан, внутреннее кольцо катушки, ось-ступица,
  выдвинутая лента с крючком, клипса на поясе
- **уровень**: каркасный корпус, три ребра жёсткости, три глазка-ампулы,
  торцевые заглушки
- **карандаш**: шестигранный корпус, продольная грань-полоса, конус-острие,
  графитовый наконечник, обжимное кольцо, ластик

**Своя орбита у каждого инструмента** — три независимых наклона (X, Y, Z):

- рулетка — X 0.55 · Z 0.25
- уровень — X −0.45 · Y 0.90 · Z 0.75
- карандаш — X 0.85 · Y −0.70 · Z −0.35

**Глубина и воздушная перспектива:**

- единая сортировка по глубине: инструмент за окном уходит за раму, перед окном —
  рисуется поверх
- добавлена **воздушная перспектива** — дальние объекты приглушаются,
  что даёт реальное ощущение объёма

## 2.2.0+41

### 3D на заставке — собственный рендерер вместо WebView

**Проблема предыдущей версии:** пакет `model_viewer_plus` поднимает внутри приложения
локальный HTTP-сервер (`http://127.0.0.1:порт`). Android 9+ блокирует такие адреса
(`net::ERR_CLEARTEXT_NOT_PERMITTED`), поэтому 3D-модель не открывалась. Починка
требовала правки `AndroidManifest.xml` в CI, но файлы workflow недоступны для записи
извне — сборка оставалась нерабочей.

**Решение:** пакет удалён полностью. 3D-просмотр написан с нуля в `lib/viewer3d.dart`:

- собственный программный рендерер: векторы, матрицы поворота, перспективная проекция
- отрисовка через `CustomPainter` методом художника (сортировка граней по глубине)
- освещение по нормали грани, полупрозрачные стеклопакеты, контуры профиля
- модель — стилизованное окно: рама, два импоста, подоконник, четыре стеклопакета
- авто-вращение + поворот пальцем, подсказка «ПОТЯНИ — ПОВЕРНУТЬ»

**Что это даёт:**

- никаких разрешений и правок манифеста — сборка APK стабильна
- работает офлайн, без интернета и внешних CDN
- APK меньше: убраны WebView и транзитивные зависимости
- 60 FPS: рендерятся только ~30 граней, без текстур и шейдеров

**Не тронуто:** логика обновления приложения (`lib/update_checker.dart`), экраны
проверки версий и установки APK, нижняя часть заставки (логотип, прогресс, кнопка).
