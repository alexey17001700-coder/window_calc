## 3.4.95+160 — балконный блок: соединительная планка 2 мм в ширине

**Что просил Босс.** У балконного блока (окно + дверь) между изделиями стоит
**соединительная планка ~2 мм**. Сейчас два нижних размера (ширина окна и ширина
двери) просто делили общую ширину сверху. Нужно: **из общей ширины сначала
вычесть планку**, и уже остаток делить между окном и дверью. Плюс — можно делать
дверь **уже или шире**, но **общая ширина при этом не меняется**.

**Новая константа (`lib/window_visual.dart`):**

- **`const int kBalconyPlankMm = 2;`** — соединительная планка балконного блока.
  **Общая ширина = ширина окна + планка + ширина двери.**

**Файл `lib/onboarding.dart`:**

- **`_balconyTotalW`** — было `окно + дверь`, стало **ведущий размер `ШИРИНА`**
  (сверху). Если сверху ещё пусто — откат на `окно + планка + дверь`
- новый метод **`_fixBalcony(src, changed)`** — пересчёт трёх размеров:
  - меняешь **ОБЩУЮ** (сверху) → окно = всего − планка − дверь
  - меняешь **ДВЕРЬ** → окно = всего − планка − дверь, **общая НЕ меняется**
  - меняешь **ОКНО** → дверь = всего − планка − окно, **общая НЕ меняется**
  - защита: ни одна часть не уходит в минус (минимум 100 мм)
- **`_askDim()`** — после ввода размера у балконного блока вызывается `_fixBalcony`
- **`_defaultSizes()`** — балконный блок: было `ШИРИНА ОКНА 1300 / ШИРИНА ДВЕРИ 700`,
  стало **`ШИРИНА 2000 / ШИРИНА ОКНА 1298 / ШИРИНА ДВЕРИ 700`**
  (2000 − 2 − 700 = 1298)
- **`_balconyControls()`** — добавлена строка
  «ПЛАНКА МЕЖДУ ОКНОМ И ДВЕРЬЮ: 2 ММ · ВСЕГО = ОКНО + ПЛАНКА + ДВЕРЬ»

**Файл `lib/window_visual.dart`:**

- **`_bWinFrac`** (попадание пальцем) и **`_winFrac`** (художник) — было
  `окно / (окно + дверь)`, стало **`окно / ВСЕГО`** — планка учтена в пропорциях
  чертежа. Формулы в обоих местах **одинаковые**, иначе тап уходил бы мимо
- в набор **`tappable`** балконного блока добавлена **`'ШИРИНА'`** — теперь
  тапается и общая ширина сверху
- **`_dimHit`** — добавлено попадание по общему размеру сверху (`'ШИРИНА'`)
- новый **`_plankStrip()`** — рисует планку на стыке окна и двери: тонкая стойка
  профиля (минимум 2 px, иначе 2 мм на 2000 мм не видно)

## 3.4.93+158 — сборка: ошибка типа в волне `screen_flash.dart` (Offset → Alignment)

**Причина падения прогона 45999895421 (прочитан `BUILD_ERROR.md`):**

```
lib/screen_flash.dart:104:36: Error: The argument type 'Offset' can't be assigned
to the parameter type 'Alignment'.
                      return _wave(origin);
                                   ^
```

**Это моя правка 3.4.90+155, а не Android-стек.** В `build()` волна запускалась
как `_wave(origin)`, а метод был объявлен с параметром `Alignment align`. Плюс
внутри него радиус стоял `1.8` — доля от размера экрана, то есть волна всё равно
заливала бы весь экран, хотя по заданию должна быть ~две ширины кнопки.

**Что исправлено (`lib/screen_flash.dart`):**

- сигнатура метода: **`_wave(Offset center, Size size)`** — точка старта в
  координатах виджета и размер области, вызов `_wave(origin, size)`
- **радиус волны теперь в пикселях и ограничен**: `maxR = 130 px`
  (ширина мягкой полосы 26 px), градиент считается с запасом под полосу
  (`gradPx = maxR + ringPx * 2`) и переводится в долю `shortestSide`
  (`radius = gradPx / shortest`) — столько и требует `RadialGradient`
- **ядро в точке старта** — тоже в пикселях: `radius: 46.0 / shortest`
  (было `0.35` от размера экрана)
- центр градиента переводится из пикселей в `Alignment` по долям размера:
  `(center.dx / size.width) * 2 - 1` — волна стартует **ровно от центра кнопки**
- защита от нулевого размера: `shortest <= 0` → пустой виджет, деления на ноль нет

**Проверка:** файл перечитан целиком после правки — вызов один, параметры
совпадают, `Alignment`/`Offset` больше не путаются, лишних вызовов `_wave` нет.

**Предупреждение NDK в логе — не ошибка.** Gradle просит NDK 27.0.12077973
(плагины `image_picker_android`, `share_plus`, `path_provider_android` и др.),
проект на 23.1.7779620. Сборку это не роняет — компиляция остановилась именно
на Dart-ошибке выше. Android-стек и workflow не тронуты.

## 2.2.0+41

### 3D на заставке — собственный рендерер вместо WebView

**Проблема предыдущей версии:** пакет `model_viewer_plus` поднимает внутри приложения
локальный HTTP-сервер (`http://127.0.0.1:порт`). Android 9+ блокирует такие адреса
(`net::ERR_CLEARTEXT_NOT_PERMITTED`), поэтому 3D-модель не открывалась. Починка
требовала правки `AndroidManifest.xml` в CI, но файлы workflow недоступны для записи
извне — сборка оставалась нерабочей.

**Решение:** пакет удалён полностью. 3D-просмотр написан с нуля в `lib/viewer3d.dart`:

- собственный программный рендерер: векторы, матрицы поворота, перспективная проекция
- отрисовка через `CustomPainter` методом художника (сортировка граней по глубине)
- освещение по нормали грани, полупрозрачные стеклопакеты, контуры профиля
- модель — стилизованное окно: рама, два импоста, подоконник, четыре стеклопакета
- авто-вращение + поворот пальцем, подсказка «ПОТЯНИ — ПОВЕРНУТЬ»

**Что это даёт:**

- никаких разрешений и правок манифеста — сборка APK стабильна
- работает офлайн, без интернета и внешних CDN
- APK меньше: убраны WebView и транзитивные зависимости
- 60 FPS: рендерятся только ~30 граней, без текстур и шейдеров

**Не тронуто:** логика обновления приложения (`lib/update_checker.dart`), экраны
проверки версий и установки APK, нижняя часть заставки (логотип, прогресс, кнопка).
