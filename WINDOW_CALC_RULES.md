# WINDOW_CALC — ПРАВИЛА РАБОТЫ (ЖЕЛЕЗНО)

Читать ПЕРЕД любой правкой этого репозитория. Правила введены приказом Босса
после серии сломанных сборок. Нарушение = брак.

## 1. ЧТО ЭТО ЗА ПРОЕКТ
Flutter-приложение под Android (APK). Сборка — GitHub Actions,
`.github/workflows/build.yml`. Версия — `pubspec.yaml`, журнал — `CHANGELOG.md`.

## 2. ЗАПРЕЩЕНО БЕЗ ПРЯМОГО ПРИКАЗА БОССА
1. Трогать `.github/workflows/build.yml` (CI). Никаких `init.gradle`, зеркал
   Maven, `concurrency`, новых шагов, «улучшений» пайплайна.
2. Трогать `android/` — Gradle, NDK, `build.gradle`, `settings.gradle`,
   `gradle-wrapper`, `gradle.properties`.
3. Добавлять или менять зависимости в `pubspec.yaml` (кроме поля `version`).
4. Подключать новые пакеты, плагины, нативные модули.
5. Менять структуру проекта, переименовывать и переносить файлы.
6. Удалять файлы.

## 3. РАЗРЕШЕНО
1. Точечные правки Dart-кода в `lib/` — строго по конкретной задаче Босса.
2. Правка `version` в `pubspec.yaml` + запись в `CHANGELOG.md`.
3. Новый `.dart` файл в `lib/` — только если Босс просил новую функцию.

## 4. ЦИКЛ ПРАВКИ (обязательный порядок)
1. `read_file` целевого файла — целиком или нужного участка.
2. `replace_in_file` — строка поиска скопирована СЛОВО В СЛОВО из файла.
3. `read_file` изменённого места — убедиться, что встало нужное.
4. Проверить, нет ли других вызовов изменённой функции (прочитать файл).
5. Поднять `version` в `pubspec.yaml`, добавить запись в `CHANGELOG.md`.
6. Отчёт: файл, что изменено, новая версия.

## 5. БЕЗОПАСНОСТЬ СБОРКИ
1. Одна задача = минимум правок. Не «улучшать» попутно.
2. Не трогать код, не относящийся к задаче. Только хирургия.
3. Правка требует нового пакета — СТОП, спросить Босса.
4. Сборка упала — сначала `read_file BUILD_ERROR.md`, потом чинить.
5. Причину падения НЕ выдумывать. Читать лог.

## 6. ЗАПРЕЩЕНО «СВОЁ ВИДЕНИЕ»
1. Не добавлять функции, которых не просили.
2. Не рефакторить «заодно».
3. Не менять анимации, темы, стили без приказа.
4. Не «оптимизировать» CI и Gradle.
5. Не менять то, что работает.

## 7. ПРИ ПАДЕНИИ СБОРКИ
1. `read_file BUILD_ERROR.md` — реальный лог, не догадка.
2. Найти первую настоящую ошибку (NDK-предупреждения — не причина).
3. Точечная правка только этого места.
4. Поднять версию, записать в `CHANGELOG.md`.
5. Не трогать CI и Gradle, если ошибка в Dart-коде.
